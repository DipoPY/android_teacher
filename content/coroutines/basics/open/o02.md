Как выбрать Dispatcher и что делает withContext?

## Hints
1. Раздели работу на UI, вычисления и ввод-вывод.
2. Main, Default, IO, main-safe функции.
3. Dispatcher определяет, на каких потоках выполняется корутина…

## Checklist
- Main — UI, Default — CPU-вычисления, IO — блокирующий ввод-вывод
- Default ограничен числом ядер, IO допускает больше потоков
- withContext переключает контекст для блока и возвращает результат
- Main-safe функции: переключение внутри suspend-функции, а не у вызывающего
- Диспетчеры можно подменить в тестах (inject)

## Follow-ups
- Зачем внедрять диспетчеры через конструктор?

## Answer
Dispatcher определяет, на каких потоках выполняется корутина:
- `Dispatchers.Main` — главный поток, работа с UI;
- `Dispatchers.Default` — CPU-вычисления, пул размером с число ядер;
- `Dispatchers.IO` — блокирующий ввод-вывод (сеть, диск, БД), допускает много потоков.

`withContext(dispatcher) { … }` выполняет блок на другом диспетчере, приостанавливая вызывающую корутину, и возвращает результат. Хорошая практика — **main-safe** функции: репозиторий сам переключается на IO внутри suspend-функции, и её можно вызывать с главного потока.

Диспетчеры стоит внедрять через конструктор, чтобы в тестах подменить их на `StandardTestDispatcher`.
